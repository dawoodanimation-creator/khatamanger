# Missing capabilities — backlog only

Audit date: 2026-10-19. **Nothing below was implemented.** These are new capabilities, not automatically authorized fixes. See AUDIT.md for the separate existing-defect list.

Priority uses the owner's definitions: P0 wrong money/data or a blocked essential task; P1 serious confusion/accessibility/safety; P2 polish or a less universal need. A high priority is not permission to build.

| ID | Priority | Screen / task | Missing capability and impact | Proposed scope if explicitly approved | Acceptance / how to verify |
| --- | --- | --- | --- | --- | --- |
| BL-01 | P0 | Transaction history / correction | No way to edit, delete or void a posted transaction. A wrong amount/customer cannot be corrected honestly; entering a fake opposite payment changes the history's meaning. | Define an auditable correction/void policy, then implement transaction-level correction with identity/amount confirmation and recalculated balances. Do not silently erase bookkeeping evidence. | Credit 100.10, payment 30.10, backdated credit 0.01; correct/void each entry and verify customer/global/running balances and JSON round trip. **Single-transaction deletion recalculation is currently not verified: the operation does not exist.** |
| BL-02 | P1 | Post-save feedback | Undo last entry is absent; users cannot immediately recover from a misplaced tap or extra zero. | A clearly bounded undo of the just-created entry, preserving the approved correction policy and preventing undo of someone else's later change. | Undo the latest entry once, repeat click, refresh, and concurrent-tab scenarios; totals/history stay consistent. |
| BL-03 | P1 | Customer deletion | Confirmation exists, but there is no undo/recovery period for deleting a customer and all their history. | Approve a recoverable-delete period or archive policy; keep it separate from permanent deletion. | Delete a customer with both credit/payment history, recover during the approved window, compare all IDs and balances. |
| BL-04 | P1 | Backup | No automatic backup reminder or last-backup guidance. | BL-06 | P1 | Shared-phone access | No optional app PIN/idle lock. ## Scope conflict to resolve before declaring the release gate passed

The owner asked for no new features, and also for zero open P0/P1. BL-01 and the seven P1 items remain open under that rule. Fixing existing bugs does not authorize these capabilities. Do not implement them disguised as shared-component fixes, silently waive them, or claim the overall zero-P0/P1 gate is satisfied. An explicit later scope decision is needed; audit-only work stops here.

Already present, so **not** missing features: search by raw stored phone string, customer edit/delete, credit/payment entry, running balances, manual balance reminders, JSON export/import, restore warning, language toggle, dark mode, demo/reset controls. Existing defects in these capabilities are listed as A-01 through A-17 in AUDIT.md.
